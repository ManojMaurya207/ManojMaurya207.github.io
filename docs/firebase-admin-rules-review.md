# Firebase admin blog rules review

Manual rules review for the blog admin flow. This is a scenario review, not an emulator penetration test.

## Assumed blog document

Collection: `blogs`; document ID is generated by Firestore and is not user-editable.

Required fields: `title` (1–120 characters), `slug` (URL-safe, 1–140 characters), `category` (1–40), `excerpt` (0–320), `content` (0–50,000), `coverImage` (empty or HTTPS, at most 2,048), `tags` (at most 8 strings), `readingTime` (integer 1–120), `isPublished` (boolean), `order` (positive integer), `createdAt` and `updatedAt` (timestamps). Only these fields are accepted.

## Identity and access

Admin access requires a signed-in Firebase Auth user whose email is `manojkumarmaurya9372@gmail.com` and whose `email_verified` claim is true. Firebase Email/Password is enabled for the project. Public users may read only published blogs; admin may list drafts and published blogs and create, update, or delete blog documents. Other portfolio collections retain public published-only reads and deny client writes.

The local Storage rules prototype permits public reads from portfolio media paths. Only the verified admin can create or replace blog images, limited to JPEG, PNG, WebP, or GIF files up to 5 MiB under `blogs/{blogId}/{fileName}`. Only the admin can delete blog media; client writes to other media paths remain denied. These rules are not deployed because Firebase Storage is not initialized in the project.

## Attack scenarios reviewed

- Unauthenticated public query for drafts: denied because a document must be published; the public app filters with `isPublished == true`.
- Unauthenticated or wrong-account blog create/update/delete: denied by the admin email and verified-email checks.
- Unverified admin email: denied.
- Create/update with missing required fields, unexpected keys, wrong field types, oversized text, malformed slug, or too many/non-string tags: denied by the same `validBlog` validator on both create and update.
- Update changing `createdAt`: denied because updates require the existing creation timestamp to remain unchanged.
- Self-assigned admin flag/custom role: not used; authorization comes from the verified identity token email, not Firestore document data.
- Client writes to profile, project, education, experience, settings, and other non-blog collections: denied.
- Non-admin Storage upload, wrong image MIME type, or image larger than 5 MiB: denied. Public reads expose only media deliberately stored in the public portfolio folders.

Rules were checked with Firebase Security Rules validation. They should still be reviewed and tested against the Firebase Emulator before broader release.
